# Opt-In Live Fixture Proof Harness

**SentinelForge** is the submitted product repository. The participant-owned [`Aayushashsahu/sentinelforge-incident-fixture`](https://github.com/Aayushashsahu/sentinelforge-incident-fixture) repository remains an external integration target; it is not copied into this repository and is never treated as product source.

`server/sentinelforge/githubFixtureProof.live.test.ts` is disabled by default. It runs only when `RUN_LIVE_FIXTURE_GITHUB_PROOF=1` is explicitly set and then requires server-side `GITHUB_SCRATCH_PR_TOKEN`, the exact `GITHUB_SCRATCH_OWNER=Aayushashsahu`, the exact `GITHUB_SCRATCH_REPO=sentinelforge-incident-fixture`, and an exact fixture-only `GITHUB_SCRATCH_CONFIGURED_CAPABILITIES` declaration for `contents:write` plus `pull_requests:write`. The declaration proves only the local configuration claim; it does not prove the effective remote token permission. Secrets, provider authorization headers, cookies, and token values are never written to source, test output, or mission evidence.

When separately authorized and explicitly enabled, the harness composes the existing real SentinelForge Investigator, Repair Engineer, fixture-gate approval capture, durable approval persistence, same-turn continuation bridge, immutable executor, audit persistence, allowlists, and write-capability policy. It requires the exact `release-manifest.json` transformation `1.3.0` → `1.4.0`, can create at most one deterministic branch, one commit, and one **open, unmerged** PR, and never merges or deletes that PR.

The harness fails closed before any protected GitHub write if the configured capability is absent, malformed, cross-repository, or mismatched to the protected operation. Immediately before a write it also verifies the immutable target and file, approval correlation, repair fingerprint, idempotency, and current base/content SHA. The exact GitHub endpoint remains the final enforcement point: **effective remote capability remains unverified until that endpoint returns**, and a `403` is persisted only as sanitized terminal evidence without retry. Read access, ownership, rulesets visibility, and a complete fine-grained-token manifest are not used as substitutes for remote acceptance; the manifest remains explicitly unverified by this REST flow. It also does **not** demonstrate sandbox verification: the real repair path remains sandbox-gated, and the harness must be enabled only under a separate live-proof authorization.

For fixture approval capture, the model does not define the target. Each fixture `get_file` call carries the persisted proof mission and action identifiers, and the MCP server derives the canonical owner, repository, base reference, permitted paths, and expected versions from the immutable action intent. The server marks `packageEvidenceVerified` or `manifestEvidenceVerified` only after the corresponding exact read succeeds; a rejected read, wrong repository, wrong reference, unexpected path, or unexpected version leaves both flags unchanged. The non-mutating fixture gate is eligible only when both flags are true for that same persisted action. Finally, SentinelForge persists an approval checkpoint only when the post-stream evidence binds both reads and the gate to the exact same provider session, turn, thread, and gate tool-call ID. A model-invoked gate alone is never authority to continue or write.
